## 1. vLLM-Omni (`vllm-project/vllm-omni`)

**Кто.** Организация `vllm-project`, автор в `pyproject.toml` — «vLLM-Omni Team». С
2026-08-17: 1827 коммитов, 356 авторов [П]. Релизы: v0.33.0rc1 (04.11), v0.32.0
(28.10), v0.31.0rc1 (06.10), v0.30.0 (25.09) [П, VO/releases]. 1982 открытых
issue+PR. Внешние issue по OmniVoice закрываются неделями–месяцами (#3182 ~2 нед.,
#3493 ~5 нед., #5659/#6333 2–3 мес., #3527 ~6 мес., #3073 открыт 7 мес.) [П].
Динамику звёзд проверить не удалось (API звёзд → 404).

**OmniVoice.** Добавлен PR [#2463](https://github.com/vllm-project/vllm-omni/pull/2463)
(03.04.2026). Сейчас — одностадийный диффузионный деплой `vllm_omni/deploy/omnivoice.yaml`:
`dtype: float32`, `max_num_seqs: 8`, `num_inference_steps: 32` [П].

**Клонирование онлайн — утверждение «только автоматический голос» устарело.**
- Код: `serving_speech.py` → `tts_adapters/omnivoice.py` принимает `ref_audio`
  (URL / data URL / file), `ref_text`, `language`, `instructions`, имя загруженного
  голоса [П]. Есть e2e-тест `TestOmniVoiceVoiceCloning` в
  `tests/e2e/online_serving/test_omnivoice_expansion.py` [П].
- `docs/serving/speech_api.md` подтверждает клонирование на `/v1/audio/speech` [П].
- **Но** `recipes/k2-fsa/OmniVoice.md` и `docs/.../online_serving/text_to_speech.md`
  до сих пор пишут «online serving for automatic voice» / «cloning requires offline» [П];
  правка доков — открытый PR [#6452](https://github.com/vllm-project/vllm-omni/pull/6452).
- Мейнтейнер 06.11 в [#3527](https://github.com/vllm-project/vllm-omni/issues/3527):
  клонирование доступно на `/v1/audio/speech`, issue закрыт 10.11 [П].
- Без `ref_text` сервер сам подгружает Whisper large-v3-turbo для расшифровки (PR #5784) [П].

**Кэш образца** [П, `diffusion/models/omnivoice/pipeline_omnivoice.py`]: LRU на 8
инлайн-образцов (токены, RMS, ref_text) + кэш загруженных голосов
(`POST /v1/audio/voices`, хранение на диске).

**Параметры** [П]: `num_inference_steps`, `guidance_scale`, `seed`,
`audio_chunk_duration`/`audio_chunk_threshold` через `extra_params`; `language`.
`speed` применяется при кодировании выхода, не в модели (вывод по коду).
`t_shift`, температуры на запрос — [Н]. Ранее `extra_params` молча игнорировались
(#3182, исправлено в мае).

**Интерфейс.**
- `POST /v1/audio/speech`, 24 кГц моно, `response_format` wav (по умолч.)/pcm/... [П].
- **Потоковой отдачи для OmniVoice нет**: диффузионный путь собирает весь результат и
  отдаёт одним ответом; `stream=true` сейчас молча даёт буферизованный ответ; открыт PR
  [#8883](https://github.com/vllm-project/vllm-omni/pull/8883) — отвечать 400 [П].
- Своя нарезка только при оценке звука > 30 с (куски по 15 с), оба порога — в запросе;
  для коротких фрагментов нарезки нет [П, PR #6409].
- Разрыв клиента ловится (`CancelledError`), освобождает ли слот диффузии — [Н].
- Батчинг шагов + CUDA graphs (PR #6408) [П].

**Паритет.** Собственная реализация генератора, декодера (DAC + свой RVQ) и Triton-ядра;
токенизатор образца — `HiggsAudioV2TokenizerModel` из transformers ≥ 5.3 [П]. PR #6408:
побитовый паритет «не гарантируется», приводят только WER [З]. Тесты паритета —
внутренние (режим запроса vs шаговый, graphs on/off), не против k2-fsa [П].
Багфиксы качества: белый шум на одном слове (#5659), пропуск слов на длинном тексте
(#6333), ref_text в выходе (#3493), не работали неречевые теги (#3954) — все закрыты [П].
Пост-обработка: вырезание пауз ≥ 500 мс, нормализация RMS, фейды, 100 мс тишины по краям [П].

**Скорость/память** [З]: A800 — fp32 572 мс / fp16 97 мс на 1,44 с звука, пик VRAM
5,5 / 4,0 ГБ (PR #6317); RTX 6000 Ada eager — p50 828 мс при 1 запросе (PR #5174).
`gpu_memory_utilization` для диффузии работает плохо — открыт #1818 [П]. Утечка диска
215–400 МБ на перезапуск из-за кэша AOT — открыт #9042 [П].

**Установка.** `uv pip install vllm==0.32.0 --torch-backend=cu130` + `vllm-omni`;
**PyTorch 2.14 + CUDA 13.0, нужен драйвер с поддержкой CUDA 13**; иначе — сборка
vLLM из исходников [П, `docs/getting_started/installation/gpu/cuda.inc.md`]. Docker:
`vllm/vllm-omni` (на базе `vllm/vllm-openai:v0.33.0`) [П]. Blackwell: RFC
[#5631](https://github.com/vllm-project/vllm-omni/issues/5631) — «нет sm_120 в CI» [П].

**Отзывы.** Открытые по OmniVoice: #3073, #9475 (ночной тест падает), #5316, #3631,
#9387. Типичное: доки расходятся с кодом, параметры игнорировались, частые падения CI.
r/LocalLLaMA: «kind of vaporware» для локального реалтайма, «vLLM is NOT easy»
([тред](https://www.reddit.com/r/LocalLLaMA/comments/1sx8c91)) — не про OmniVoice.
Продакшен-использования OmniVoice в голосовых агентах [Н].

**Лицензия:** Apache-2.0.

## 2. audio.cpp (`0xShug0/audio.cpp`)

**Кто.** Репо пользователя, копирайт «ShugoAI LLC»; создан 23.06.2026, 4315 звёзд,
526 форков [П]. С 17.08: 903 коммита, 122 автора, из них 0xShug0 — 504 (56 %);
~500 смерженных внешних PR [П]. Релизы каждые 1–2 нед.: v0.9.5 (14.11), v0.9.4 (05.11),
v0.9.3 (26.10)… [П]. Медиана закрытия последних 20 issue ~4 ч [П]. Звёзды: список
скрыт (REST 404, GraphQL пусто) — проверить на накрутку нельзя [Н]; источник роста —
регулярные посты автора на r/LocalLLaMA (84–421 голос) [П]. Соотношение форков и
внешних PR указывает на реальную активность (вывод).

**OmniVoice.** С первого коммита; 31 коммит по модели; свежее — нативный батчинг ~2×
на CUDA ([#1208](https://github.com/0xShug0/audio.cpp/pull/1208), 06.11),
выравнивание длительности и нормализации текста с Python (#1110, #1116) [П].
- Клонирование на сервере: `voice_ref` (путь или base64 до 5 МиБ) + `reference_text`,
  либо `voice: "<имя>"` из `voice_dir` с файлом транскрипта [П, `app/server/api.md`].
- Кэш образца: **один слот** на сессию модели (хэш сэмплов); тот же голос не
  перекодируется, смена голоса — перекодирование. Сохранения токенов голоса в файл нет [П,
  `src/models/omnivoice/session.cpp`, [#484](https://github.com/0xShug0/audio.cpp/issues/484)].
- Параметры: `num_inference_steps` (32), `guidance_scale` (2.0), `language`, `seed`,
  `instruct`, `speed`, `duration_sec`, `shift`, `denoise`, `preprocess_prompt`,
  `postprocess_output`, температуры [П, `docs/models/omnivoice.md`]. `speed` работает
  (#689) [П]. Русский в карте языков есть; русских тестов/отзывов [Н].

**Интерфейс** [П, `app/server/api.md`, `app/server/README.md`]:
- `POST /v1/audio/speech` (поля `model`, `input`, `voice`, `speed`, `options{}`), WAV
  по умолчанию; PCM — в потоковом режиме (SSE `speech.audio.delta` или сырой chunked PCM).
- Частота дискретизации берётся из конфига токенизатора; явно «24 кГц» в доках [Н].
- Потоковость — «chunked pseudo streaming»: событие на каждый фрагмент текста; требует
  отдельной записи модели с `mode: "streaming"`.
- Нарезка: фреймворковая выключена по умолчанию; модельная — только при оценке > 30 с,
  порог в запросе. Т. е. «фрагмент → звук» — поведение по умолчанию.
- Отмена: SSE-клиент отключился → прогон останавливается через 1–2 события; JSON-клиент
  → прогон досчитывается. «Hard backend cancellation» для параллельного режима не проверена.
- Параллелизм: по умолчанию 1 запрос на модель, остальные ждут → 503 `server_busy`;
  `--parallel-jobs` экспериментален. Модель целиком на одном устройстве (2 GPU = 2 записи).

**Паритет.** Полный порт на C++/ggml: генератор, аудиотокенизатор (энкодер+декодер),
текстовый токенизатор, пост-обработка [П]. GGUF: `q8_0`, `bf16`, `f16` + загрузка
исходных safetensors; активации в основном f32 [П, `model_specs/omnivoice.json`].
Аудиотокенизатор в q8_0 даёт «непригодный звук» (оценка на слух авторов) [З,
`docs/reports/omnivoice_weight_type_benchmark.md`]. Тесты паритета — C++ против C++
(побитово в f32); **сравнения с Python по звуку (SNR/WER) нет** [Н]. Длина выхода
отличается от Python на −29…+30 % (медиана +0,7 %) [З, `docs/reports/omnivoice_concurrency_benchmark.md`].
Жалобы: утечка ref-текста и пропуск слов на длинных текстах (#27, исправлено/списано на
модель), качество на Vulkan/Adreno (#603) [П]. Про ударения/русский [Н].

**Скорость** [З, тот же отчёт]: RTX 4090, CUDA 12.6, **16 шагов**, бенгальский: C++
flash_attention f16 112/182 мс (10/20 слов); Python+FlashInfer+CUDA graphs 213/277 мс;
чистый PyTorch 985/1152 мс. На 32 шагах (до #1208) f16 ~689 мс. Пиковая пропускная
способность выше у Python+FlashInfer в 5–6 процессах. README: «1.8–8× быстрее Python» [З].
Память: «утечка» в #27 оказалась аллокацией 36 ГБ под длинный образец, исправлено
(~4 ГБ после) [П]; есть CI `server-memory-guard.yml`; отчётов об утечках при долгой
работе [Н].

**Установка** [П]: Linux CUDA — только библиотеки (`lib-ubuntu-x64-cuda12.8`,
`cuda13.3`) и colab-бинарник, готового серверного бинарника для Ubuntu+CUDA нет;
Docker `ghcr.io/0xshug0/audio.cpp:full-cuda12` (база CUDA 12.9.2 — на драйвере 550
не запустился, [#504](https://github.com/0xShug0/audio.cpp/issues/504)) и `:full-cuda13`;
сборка: CMake ≥ 3.20, GCC ≥ 13, CUDA toolkit; при toolkit ≥ 12.8 добавляется
`120a-real` [П, `CMakeLists.txt`]. Blackwell: RTX 5090 D падение в cublasLt (Windows,
причина — выключенный AVX-512, #1187), долгий прогрев CUDA graphs на 5070 Ti (#101,
исправлено) [П]. Отчётов по 5060 Ti / Linux [Н].

**Отзывы.** Открытых issue по OmniVoice нет (кроме трекера #484) [П]. Reddit:
пользователь использует audio.cpp как TTS в своём голосовом агенте
([тред](https://www.reddit.com/r/LocalLLaMA/comments/1v4w5cj/)) [З]; pyVideoTrans
рекомендует OmniVoice через audio.cpp по умолчанию [П]. Habr/HN про audio.cpp [Н].

**Лицензия:** Apache-2.0 (GitHub показывает NOASSERTION из-за шапки) [П].

## 3. RealtimeTTS (`KoljaB/RealtimeTTS`)

**Кто.** Фактически один автор: KoljaB 524 коммита, следующий — 22 [П]. За 3 мес. —
почти всё KoljaB + несколько внешних PR; один коммит от «Codex» (PR #387) — часть
сопровождения делает ИИ-агент [П]. 4060 звёзд, с 08.2023. Релизы всплесками
(0.8.8–0.8.10 за 26–27.09, затем тишина), теги v0.9.0rc4–rc7 не на PyPI [П].
Issue после января 2026 среди закрытых не встречаются; старые закрывались от дней
до года+ [П]. Фокус последних месяцев — Qwen3-TTS, не OmniVoice [П].

**OmniVoice.** `RealtimeTTS/engines/omnivoice_engine.py`, с 0.6.1 (апр. 2026) [П].
- Модель грузится **в процессе** (`from omnivoice import OmniVoice`), не внешний сервер [П].
- `OmniVoiceVoice(name, ref_audio, ref_text, language)` — обязательны оба [П].
- Шаги по умолчанию `[12, 32]`: первое предложение — 12 шагов, далее 32 [П].
- **Образец кодируется заново на каждом предложении**: в `generate()` передаётся
  `ref_audio=...`, `voice_clone_prompt` не используется [П].
- `guidance_scale`, `speed` не выставлены — upstream-умолчания [П].
- Падение на numpy (#374) исправлено в master 17.10, **в PyPI 0.8.10 баг остаётся** [П].
- Документация движка: «speed tuning did not promote OmniVoice above the faster local paths» [З].

**Интерфейс.** Библиотека (`TextToAudioStream(engine).feed(...).play()`), не сервер.
Пример FastAPI-сервера — без OmniVoice, 1 запрос за раз. OpenAI-совместимый
`qwen_server.py` — только Qwen [П]. Выход 24 кГц int16 моно, одно предложение = один
чанк [П]. `stop()` выставляет флаг, но движок OmniVoice его не проверяет:
текущее предложение досчитывается, звук отбрасывается [П]. «Тупой» режим возможен
только обходным путём (вызывать `engine.synthesize()` напрямую) — не документирован [П].

**Что берёт на себя (пересечение с ролью Go-модуля)** [П, `text_to_stream.py`,
`stream_player.py`]: нарезка на предложения (stream2sentence, NLTK/правила/stanza, быстрый
первый фрагмент); очередь предложений + поток упреждающего синтеза; склейка предложений
по порогу буфера; вставка пауз по знаку препинания; воспроизведение через PyAudio
(пауза, громкость, устройство, ресэмплинг); стоп/прерывание; колбэк чанков; запись WAV;
тайминги слов; список запасных движков. Т. е. практически всё, что владелец хочет
держать в Go, — но в Python-процессе вместе с моделью.

**Паритет.** Тот же пакет `omnivoice`, fp16, `clip*32767 → int16` без ресэмплинга [П].
Отличие от наших настроек — 12 шагов на первом предложении. Жалоб на качество
OmniVoice [Н].

**Скорость/память.** Цифр по OmniVoice нет (README — про Qwen на 4090) [Н]. Рост
памяти GPU со временем — открытый [#360](https://github.com/KoljaB/RealtimeTTS/issues/360)
(Coqui, не OmniVoice) [П].

**Установка.** `pip install "realtimetts[omnivoice]"`, torch/CUDA — на пользователе,
PortAudio для PyAudio; Docker для OmniVoice нет [П]. RTX 50xx [Н].

**Отзывы.** Открытые OmniVoice-issue: #374, #376 (запрос GGUF). Общие: заикания и
недозаполнение буфера (#322, #285, #272) [П]. Используется в собственных проектах
автора (RealtimeVoiceChat — Show HN, ~500 мс с Coqui/Kokoro [З]) [П].

**Лицензия:** Apache-2.0 с 10.11.2026; PyPI 0.8.10 — MIT [П].

## Что я проверил рядом (одной строкой)

- **sherpa-onnx (k2-fsa)** — OmniVoice **не поддерживается**: запрос
  [#3651](https://github.com/k2-fsa/sherpa-onnx/issues/3651) открыт, мейнтейнер требует
